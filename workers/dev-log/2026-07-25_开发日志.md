## 🧠 二、 核心经验总结 (Experiences & Learnings)

1. **分布式 Userscript 遥测的同源与 CORS 原则**
   - 油猴脚本运行在宿主域名上下文中，其发出的 HTTP POST 请求头受到宿主 CORS 策略限制。Worker 后端必须使用动态 `origin || '*'` 响应 `Access-Control-Allow-Origin`，并将自定义鉴权头（`X-MP-Token`, `X-MP-Ts`, `X-XFlow-Token`, `X-XFlow-Ts`）明确加入 `Access-Control-Allow-Headers` 白名单中。

2. **SQLite / Serverless D1 的写配额成本意识**
   - 在 Cloudflare D1 中，`INSERT ... ON CONFLICT DO UPDATE` (UPSERT) **同样计算为 1 次 Write Operation**。
   - 高频 Session 聚合必须尽量做到“单请求单表写入”。频繁变化的数据合并为 JSON 存单行，低频变化的数据（如用户 User-Agent、首次访问时间）必须按需异步更新，切忌随 Batch 定时器无脑连带更新。

3. **绝对无损数据 ID (Canonical ID) 提取思想**
   - 对于第三方 CDN (如 Twitter/twimg) 规则复杂、没有统一 RESTful ID API 的视频资源，**绝对不要尝试做有损的正则剥离（如只留纯数字）**。
   - 应保留带有完整目录结构与文件名哈希的相对 Path 作为 ID 标识，既能作为全局唯一主键，又能在任何节点无缝拼接 CDN 域名恢复播放。

## ⚠️ 三、 教训与避坑指南 (Pitfalls to Avoid)

### ❌ 坑点 1：前端预加载/初始化逻辑脱离用户意图
- **现象**：为了追求所谓的“缩短评论加载等待”，在脚本启动 `startScript()` 时无条件自动调用 `CommentPanel.preload()`。
- **教训**：用户在含有视频的网页上浏览，绝大多数情况下可能完全不需要打开播放器看评论。脚本静默预加载不仅浪费用户流量，还会引发不必要的跨域请求与垃圾遥测上报。
- **避坑法则**：**延迟按需加载 (Lazy Initialization on Demand)**。所有非核心核心 UI 的重型接口（如评论抓取、高清解析），必须严格限制在用户主动触发（如点击播放器、切换 Tab）后再启动。

### ❌ 坑点 2：Worker 端参数清洗正则过于苛刻破坏业务 ID
- **现象**：旧版 Worker 中的 `sanitizeStr` 采用 `replace(/[^\w\-_.]/g, '')` 且限制长度 64，导致全路径 ID `amplify_video/.../xxx.mp4` 入库时斜杠 `/` 被彻底擦除，字符串被裁切毁坏。
- **教训**：后端安全清洗不可盲目一刀切。当业务 ID 需要承载路径或特定符号时，必须在正则白名单中放行 `/` `@` `:` `=` `?` 等字符，并留足安全长度（如 256 字符）。

### ❌ 坑点 3：定时器防抖覆盖逻辑导致的“请求饥饿”
- **现象**：之前的 `scheduleFlush` 在长定时器（15 分钟）激活时，直接 `return` 放弃处理紧急事件。
- **教训**：当发生 `app_init` 或 `player_close` 等重要关键事件时，长定时器必须立刻被 `clearTimeout` 销毁，并在 1 秒内强制执行 `flush()`，防止页面被用户直接关闭导致关键会话数据丢失。
