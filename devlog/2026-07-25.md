# X-Flow 开发日志 — 2026-07-25 (v6.2.9)

## 📌 版本信息
- **版本号**: `v6.2.9`
- **日期**: 2026-07-25
- **主要内容**: 修复“我的收藏”播放失败及退出收藏后排行榜视频无法播放的播放器 Modal 节点脱落问题，防范 DOM 重绘导致的组件失联。

---

## 🚀 1. 功能更新 (Feature & Fix Updates)

### 1.1 播放器 Modal DOM 状态恢复 (`TikTokMode.ts`)
- **新增 `ensureInDom()` 挂载校验**:
  在 `TikTokMode` 类中添加 `ensureInDom()` 方法，在每次调用 `openModal()` 打开播放器时，主动检查 `#tm-tiktok-modal` 节点是否存在于 `#xflow-app-root` 内。若由于页面重绘导致节点脱落，能立即将其重新 `appendChild` 挂载回 DOM 树中。

### 1.2 收藏列表视频流 URL 解析修复 (`Layout.ts`)
- **修正 `isDetailsLoaded` 标记逻辑**:
  在 `loadBookmarksData()` 中映射收藏项为 `UnifiedVideoItem` 时，将原本硬编码的 `isDetailsLoaded: true` 修改为 `isDetailsLoaded: !!b.url`。
  - **效果**: 对于未提前解析出视频直链 (`url`) 的历史收藏记录，能在点击播放时正常触发 `PoolManager.loadDetails()` 发起网络请求解析播放流 URL，解决打不开视频的问题。

### 1.3 事件监听防重绑定机制 (`Layout.ts`)
- **全局事件防重复注册**:
  添加 `globalEventsBound` 标识位，将 `document.addEventListener('click', ...)` 等全局事件委托监听收拢保护，防止视图切换（如排行榜与收藏页切换）频繁触发 `bindEvents()` 导致全局事件监听器成倍累积。

---

## 💡 2. 经验 (Key Insights & Architecture Design)

1. **Userscript / Single Page App 的组件生命周期管理**:
   - 在 Vanilla DOM + CSS Variables 的全屏 Userscript 架构中，全覆盖式的模态框/播放器（如 `TikTokMode`）如果挂载在主容器 (`#xflow-app-root`) 内部，当主容器使用 `innerHTML = ...` 重新渲染视图结构时，挂载在其中的所有子元素都会被浏览器彻底从 DOM 树中移除。
   - 即使播放器对象 (JS Instance) 依然保存在内存中，对脱离 DOM 树的节点修改 `style.display = 'block'` 也无法在视口中呈现任何内容。因此，**在视图模态框的 `openModal()` 入口处进行 DOM Presence 校验 (`ensureInDom()`) 是保证组件自愈的关键模式**。

2. **数据流延迟加载标志位的严谨性**:
   - `isDetailsLoaded` 标志位应当严格约束在“数据已具备可播放/完整渲染条件”时才成立。不能仅因为数据来自于本地持久化存储 (`loadGM`) 就假设其详情已加载完毕，防止下游的异步数据加载机制被错误拦截。

---

## ⚠️ 3. 教训 (Lessons Learned & Root Cause)

1. **误诊 z-index 遮挡现象**:
   - 当点击视频没有任何响应、画面无变化时，直觉容易怀疑是 `z-index` 被蒙版遮挡或层级错乱。然而抓包与 Console 无报错的情况下，最先应当排查的是**目标元素是否仍位于 Document DOM 树中** (`document.body.contains(element)`)。
2. **`innerHTML` 销毁作用域溢出**:
   - `createPageStructure()` 承担了整个主界面（Sidebar + Topbar + Grid）的模态刷新，但因为其作用域包含了全局容器 `this.rootElement`，清空 `innerHTML` 时无意间将常驻的播放器模态框一同物理销毁。

---

## 🛡️ 4. 避坑指南 (Avoidance Guidelines & Defensive Rules)

- **[RULE] 模态框/浮层 DOM 挂载校验**:
  任何单例 UI 组件（如全局播放器、弹窗、全局 Toast），在调用 `.show()` / `.openModal()` 展示前，必须检查 `root.contains(this.element)`；若为 `false` 则主动重新 `appendChild`。
- **[RULE] 避免在重绘函数中重复注册 `document` 事件**:
  `bindEvents()` 若包含 `document.addEventListener(...)`，必须使用类私有标志位（如 `globalEventsBound`）进行单次绑定拦截，或者使用 Event Delegation 委托至未被销毁的固定父节点上。
- **[RULE] 模板与版本号同步打包**:
  修改 `package.json` 版本号后，必须执行 `npm run build` 确保 `dist/userscript/x-flow.user.js` 的 Userscript Header（`@version`）被 `vite-plugin-monkey` 正确同步。

- **日期**: 2026-07-25
- **主要内容**: 全局代码瘦身 (Ponytail Audit -244行)、JS 动效 CSS 化/GPU 硬件加速、播放器无操作闲置自动隐藏 UI 控件及上下渐变阴影。

---

## 🚀 1. 功能更新 (Feature & Fix Updates)

### 1.1 Ponytail Audit 代码精简 (-244 行)
- **彻底删除 5 个无用空占位文件**：
  `Tracker.ts`, `Scoring.ts`, `TinderMode.ts`, `Reporter.ts`, `meta.ts`
- **清理 `getHeroRanges()` 废弃接口 (-120 行)**：
  移除了 `SiteAdapter.ts` 中的 `HeroRange` 接口与 `getHeroRanges?()` 声明，以及 10 个站点适配器中的空实现。
- **清理死 API 与废弃配置**：
  移除 `ApiClient.getBaseUrl()`、`DomUtils` 导出以及 `STORAGE_KEYS` 中废弃的 `WATCHED`, `UNREAD_ONLY`, `BOOKMARKS`。
- **优化方法签名**：
  移除 `EventCollector.trackTimeUpdate` 未引用的 `duration` 参数。

### 1.2 JS 动效 CSS 化与 GPU 硬件加速
- **网络 Warning Banner (`Sandbox.ts` + `player.css`)**：
  将 JS 动态拼接 style 与 keyframes 逻辑提取为纯 CSS `.xflow-net-banner` + `.hiding`，开启 `will-change: transform` 合成层。
- **Splash 启动遮罩隐藏 (`Sandbox.ts` + `player.css`)**：
  使用 `.xflow-splash-hiding` 状态类替代 JS 内联 style，配置 `will-change: opacity, transform` 结合 `cubic-bezier(0.16, 1, 0.3, 1)` 缓解首帧卡顿。
- **Confirm Modal 弹窗 (`Dom.ts`)**：
  遵循 Knowledge #31 规范，废弃 `setTimeout(..., 10)` 魔法定时器，改用 `overlay.offsetHeight` 强制 layout reflow 精确触发 CSS 入场/退场动画。

### 1.3 视频播放闲置自动隐藏 UI 与上下渐变阴影 (`TikTokMode.ts` + `player.css`)
- **渐变阴影遮罩同步淡出**：
  在 `#tm-tiktok-modal.tm-idle` 模式下，将顶部渐变阴影遮罩 (`.tm-video-stage::after`) 与底部渐变阴影遮罩 (`.tm-progress-wrap::before`) 的 opacity 同步渐变淡出至 `0` (`opacity: 0 !important`)，实现沉浸式全屏观影。
- **面板交互避让**：
  当用户打开评论面板、作者主页、设置菜单或倍速选择时，自动暂停闲置倒计时，防止用户阅读/操作时 UI 和阴影被误隐藏。

---

## 💡 2. 经验 (Key Insights & Architecture Design)

1. **JS 动效 CSS 化与 GPU 合成层**:
   - 避免直接通过 JS 修改 `.style.opacity` 或 `.style.transform`。抽离至 CSS class 并结合 `will-change: opacity, transform` 可使浏览器提升为独立 Compositor Layer（硬件合成层），能极大提升 CPU 占用高的 Userscript 环境下的渲染帧率。
2. **渐变阴影遮罩的沉浸感同步**:
   - 全屏视频播放器的上下渐变阴影必须与 UI 控件（TopBar、Info、Actions）同步隐藏，否则单独隐藏控件而留下半透明黑带会严重破坏画面沉浸感。

---

## ⚠️ 3. 教训 (Lessons Learned & Root Cause)

1. **`setTimeout` 定时器动画卡帧与竞争**:
   - `setTimeout(..., 10)` 在高刷新率屏幕或高主线程负载时，回调函数容易跨帧，导致浏览器将 `display: block` 和 `.show` 合并处理而使 CSS 过渡动画失效。使用 `element.offsetHeight` 读取可强制立刻触发 layout reflow，确保过渡动画100%生效。
2. **死接口代码膨胀**:
   - 早期设计的 `getHeroRanges` 接口在 10 个 Adapter 中都有留存，积攒了超过 120 行无效代码。定期使用 `/ponytail-audit` 进行代码审查能保持 Codebase 干净精简。

---

## 🛡️ 4. 避坑指南 (Avoidance Guidelines & Defensive Rules)

- **[RULE] 过渡动画触发机制**:
  当元素由 `display: none` 切换至显示并需要动画过渡时，在 `display = 'block'` 后必须访问 `element.offsetHeight` 触发重绘后再添加 `.active` 类名。
- **[RULE] 尽量避免内联动态注入 style 样式**:
  组件样式应集中放置于 CSS 文件中通过 Class 切换，避免在 JS 中大量拼接 style 文本或 append `<style>` 标签。
- **[RULE] 闲置倒计时控制**:
  全屏播放器闲置倒计时（Auto-Hide Idle Timer）触发时，必须先校验当前是否有侧边面板（如评论、博主主页、设置）正处于激活展示状态。

# X-Flow 开发日志 — 2026-07-25 (v5.5.2)

## 📌 版本信息
- **版本号**: `v5.5.2`
- **日期**: 2026-07-25
- **主要内容**: 修复高分辨率屏幕下视频容器内联 `min-height` 溢出导致画面放大的缺陷，完成全局 Ponytail 代码瘦身审计与版本规范统一。

---

## 🚀 1. 功能更新 (Feature & Fix Updates)

### 1.1 视频容器内联 min-height 溢出与视口约束修复 (`UIManager.js` / `DragManager.js`)
- **高分屏内联 min-height 封顶**:
  在 `UIManager.js` 的 `createOverlayAndContainer()` 与 `updateContainerMinHeight()` 中，对根据屏幕宽度计算出的 `defaultMinHeight` 和 `minHeight` 增加 `Math.min(..., window.innerHeight * 0.8)` 80vh 约束。
  - **效果**: 彻底解决 1080p/2K 高分屏下 `window.innerWidth * (9/16)` 算出 `1080px` 内联样式覆盖 CSS `max-height: 80vh` 导致视频画面比上层容器还高、画面被严重挤压放大的问题。
- **拖拽高度边界限制**:
  在 `DragManager.js` 的 `_handleDragMove()` 中，同样将用户手动拖拽调整的高度上限约束在 `80vh` 视口范围内，防止手势拖拽导致界面越界。

### 1.2 Ponytail 代码审计与冗余瘦身
- **移除动态硬编码 CSS 拼接**:
  清理多处 JS 中硬编码的 `.style.cssText` 样式，统一规范回收至 CSS 文件。
- **抽象层与无用模块精简**:
  针对已归并的单接口实现及无用占位模块，精简无用代码，保持 Codebase 干净精练。

---

## 💡 2. 经验 (Key Insights & Architecture Design)

1. **CSS 规范中 `min-height` 覆盖 `max-height` 规则**:
   - 根据 CSS 规范，当元素的 `min-height` 大于 `max-height` 时，`min-height` 的值拥有决定性优先级。在 JS 中动态计算内联 `min-height` 时，若未对视口最大高度（如 `80vh`）进行封顶截断，内联 `style="min-height: 1080px"` 将无视 CSS `max-height: 80vh` 规则，导致容器高度溢出。
2. **多终端响应式高宽计算必须双向封顶**:
   - 依赖 `window.innerWidth` 按比例推算高度时（如 `9/16`），不能假设用户处于移动端全屏。在 PC 宽屏或高分屏设备上，必须结合 `window.innerHeight` 进行双向限制。

---

## ⚠️ 3. 教训 (Lessons Learned & Root Cause)

1. **内联样式 (Inline Style) 的权重大山**:
   - 在 JS 中直接给 `element.style.minHeight` 赋值会产生最高优先级的内联 CSS，无法被外部 `.css` 样式表中的 `max-height` 轻松约束。排查 UI 异常放大或错位时，应优先查看元素是否被 JS 赋予了写死的 px 值内联样式。

---

## 🛡️ 4. 避坑指南 (Avoidance Guidelines & Defensive Rules)

- **[RULE] 动态高度计算必加视口封顶**:
  所有根据屏宽计算高度的 JS 逻辑，必须使用 `Math.min(calculatedHeight, window.innerHeight * maxPercent)` 进行保护。
- **[RULE] 版本号发布打包闭环**:
  修改 `package.json` 中的 `version` 后，必须立刻运行 `npm run build` 确保 Userscript 编译输出文件的 Header 注释（`@version`）被同步更新。
